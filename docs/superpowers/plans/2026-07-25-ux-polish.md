# UX Bug Fixes + Visual Polish Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Fix four verified UX bugs (toast overlap, mobile layout order, silent role-distribution validation failure, untranslated faction name) and add five small, additive polish touches on top of the app's existing design-token and animation system, without duplicating the animation work already shipped in `docs/superpowers/specs/2026-07-19-game-feel-polish-design.md`.

**Architecture:** Every task is a small, isolated change to one existing component (CSS-only where possible, minimal TS where behavior is needed). No new routes, no new services beyond one tiny presentation directive, no backend/API changes.

**Tech Stack:** Angular 22 (standalone components, signals), SCSS, `@ngx-translate/core` for i18n, existing Playwright e2e suite for regression coverage.

## Global Constraints

- No new color palette or font stack — reuse existing tokens (`--color-*`, `--font-title/ui/body`, and `room-shell`'s local `--primary`/`--accent-day`/`--accent-night`/`--danger`/`--success` tokens) throughout.
- `room-shell.scss` intentionally opts its own headings/buttons back into Inter instead of the gothic `--font-title`/`--font-ui` pair — do not touch that override.
- No changes to game rules, HTTP endpoints, or SignalR command/notification shapes — this is a pure frontend visual/UX pass, so `GAME_FLOW.md` / `docs/api-and-signalr-commands.md` / `../werewolf/GAME_FLOW.md` do not need updates (per `CLAUDE.md`'s doc-sync rule — confirm this still holds at the end; if any task turns out to touch a wire shape, stop and update those three docs before committing it).
- All new motion must respect `prefers-reduced-motion` (every existing animation in this codebase already follows this pattern — match it).
- Never add a `Co-Authored-By` trailer to any commit in this repo.
- `npm run e2e` must pass unmodified after every task that touches a screen its specs cover.

- [ ] **Step 1: Make `dismiss` two-phase — mark leaving, then remove after the exit animation's duration**

In `src/app/core/services/toast.service.ts`, add `leaving` to the interface and split `dismiss`:

```ts
export interface Toast {
    id: number;
    message: string;
    kind: ToastKind;
    leaving?: boolean;
}

const AUTO_DISMISS_MS = 4500;
const MAX_VISIBLE_TOASTS = 3;
const EXIT_ANIMATION_MS = 200;

@Injectable({ providedIn: 'root' })
export class ToastService {
    private nextId = 1;
    readonly toasts: WritableSignal<Toast[]> = signal([]);

    show(message: string, kind: ToastKind = 'info'): void {
        const id = this.nextId++;
        this.toasts.update((toasts) =>
            [...toasts, { id, message, kind }].slice(-MAX_VISIBLE_TOASTS)
        );
        setTimeout(() => this.dismiss(id), AUTO_DISMISS_MS);
    }

    dismiss(id: number): void {
        this.toasts.update((toasts) =>
            toasts.map((toast) => (toast.id === id ? { ...toast, leaving: true } : toast))
        );
        setTimeout(() => {
            this.toasts.update((toasts) => toasts.filter((toast) => toast.id !== id));
        }, EXIT_ANIMATION_MS);
    }
}
```

(`.slice(-MAX_VISIBLE_TOASTS)` in `show` still works unchanged — it caps the array length regardless of any `leaving` flags on the entries it keeps.)

Implemented as an attribute directive (not a wrapping component) specifically so it stays on the existing `<strong>` element already styled by `room-shell.scss`'s `.room-shell__stat strong` rule — Angular's emulated view encapsulation means a child component's own template markup wouldn't pick up that descendant selector, but an attribute directive applied to an element already in `room-shell`'s own template does.

- [ ] **Step 1: Write the directive**

Create `src/app/shared/directives/animated-count.directive.ts`:

```ts
import { Directive, ElementRef, effect, inject, input } from '@angular/core';

const TWEEN_DURATION_MS = 450;

/** Tweens an element's text content from its previous numeric value to a new one whenever the
 * bound value changes, instead of the number snapping instantly. Applied as an attribute
 * directive (not a wrapping component) so it stays on the caller's own element and keeps
 * whatever CSS already targets it. */
@Directive({
    selector: '[appAnimatedCount]'
})
export class AnimatedCount {
    private readonly el = inject(ElementRef<HTMLElement>);
    private displayedValue: number | null = null;
    private frameHandle: number | null = null;

    readonly appAnimatedCount = input.required<number>();

    private readonly reducedMotion =
        typeof matchMedia === 'function' && matchMedia('(prefers-reduced-motion: reduce)').matches;

    constructor() {
        effect(() => {
            const target = this.appAnimatedCount();
            const from = this.displayedValue ?? target;
            this.displayedValue = target;

            if (this.reducedMotion || from === target) {
                this.render(target);
                return;
            }

            this.tween(from, target);
        });
    }

    private tween(from: number, to: number): void {
        if (this.frameHandle !== null) {
            cancelAnimationFrame(this.frameHandle);
        }
        const start = performance.now();
        const step = (now: number): void => {
            const progress = Math.min(1, (now - start) / TWEEN_DURATION_MS);
            const eased = 1 - (1 - progress) * (1 - progress);
            this.render(Math.round(from + (to - from) * eased));
            if (progress < 1) {
                this.frameHandle = requestAnimationFrame(step);
            } else {
                this.frameHandle = null;
            }
        };
        this.frameHandle = requestAnimationFrame(step);
    }

    private render(value: number): void {
        this.el.nativeElement.textContent = String(value);
    }
}
```

### Task 9: Stagger the Game Over role-card reveals

**Files:**

- Modify: `src/app/shared/components/player-grid/player-grid.html`
- Modify: `src/app/shared/components/animated-card/animated-card.scss`

**Interfaces:** None — pure CSS custom-property plumbing through existing markup.

**Approach:** `PlayerGridEntry.revealedRole` is set on every entry simultaneously by `room-shell.ts`'s `entries()` computed when the game ends, so every `app-role-card`'s `[revealed]="true"` binding flips true in the same Angular change-detection tick today. Rather than restructure that computed into a time-staged sequence, stagger the _visual_ flip by giving each card's CSS transition a per-index `transition-delay` — the class change still happens all at once, but the animation each one runs starts at a different time.


- [ ] **Step 2: Consume the custom property in the flip transition**

`--reveal-delay` cascades as a normal inherited-by-declaration CSS custom property from `.player-grid__reveal` down through `app-role-card` into `app-animated-card`'s `.animated-card__face` (custom-property inheritance crosses Angular component boundaries the same as any other CSS inheritance — it isn't scoped by view encapsulation). In `src/app/shared/components/animated-card/animated-card.scss`, add the delay to the existing transition:

```scss
&__face {
    @include mixins.card-frame;

    position: absolute;
    inset: 0;
    backface-visibility: hidden;
    transition:
        transform 0.6s ease,
        transform 0.6s ease var(--reveal-delay, 0ms);
    display: flex;
    align-items: center;
    justify-content: center;
    overflow: hidden;
}
```

Wait — a single property can't have two transition entries both matching `transform` meaningfully; only one delay actually applies (the second listed wins in some engines, is undefined behavior in intent). Use this instead — a single `transform` transition whose delay is _only_ ever nonzero on the game-over reveal path (`--reveal-delay` defaults to `0ms` everywhere else, e.g. night-action player cards or the identity grimoire, which never set that custom property):

```scss
&__face {
    @include mixins.card-frame;

    position: absolute;
    inset: 0;
    backface-visibility: hidden;
    transition: transform 0.6s ease var(--reveal-delay, 0ms);
    display: flex;
    align-items: center;
    justify-content: center;
    overflow: hidden;
}
```

This is a strict superset of the original `transition: transform 0.6s ease;` — `var(--reveal-delay, 0ms)` resolves to `0ms` (i.e. identical behavior to today) everywhere the custom property isn't explicitly set, and only the Game Over grid's reveal wrapper ever sets it.
